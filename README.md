# GIS & Remote Sensing Portfolio

A static portfolio generated with Python, Jinja2, and reproducible geospatial workflows. GeoPandas, PyProj, Rasterio, NumPy, and Matplotlib create the maps; the published site needs no Python server. The Projection Lab uses a locally bundled D3 renderer for live panning, zooming, country labels, and projection changes from Python-generated GeoJSON.

## Setup

Requires Python 3.11 or newer.

```bash
python -m venv .venv
# Windows (Git Bash)
source .venv/Scripts/activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -e .
```

The bundled interactive map is included, so Node is not needed for normal content or GIS changes. To modify `web/projection-map.js`, install Node 22 or newer and rebuild the browser bundle:

```bash
npm ci
npm run build
```

## Generate maps and preview

For routine previews, use the reviewed assets already in `static/generated/`:

```bash
portfolio-build
python -m http.server 8000 --directory dist
```

Open `http://localhost:8000`. Run `portfolio-maps` locally only when intentionally changing source data, GIS code, or cartography. The first regeneration downloads Natural Earth data and reads a Dublin study-area window from public Sentinel-2 cloud-optimized GeoTIFFs; later runs reuse local inputs cached in `data/raw/`. Review and commit the resulting files under `static/generated/` with the related source changes. Deployment never performs this data-processing step.

For a GitHub Pages project site, pass its repository base path:

```bash
portfolio-build --base-path repository-name
```

## Edit the portfolio

- Personal details and professional links: `content/site.json`.
- Project writing, map captions, methods, and data citations: `content/projects/*.json`.
- Projection descriptions: `content/projections.json`.
- Page layouts: `templates/`.
- Colors, layout, and responsive styling: `static/css/site.css`.
- Tabs and project filters: `static/js/site.js`.
- Interactive projection source: `web/projection-map.js`; run `npm run build` after editing it.
- Map workflows and GeoJSON export: `portfolio_gis/gis/`.

After editing content or templates, run `portfolio-build`. After intentionally changing GIS code or inputs, run `portfolio-maps`, review the results, and commit the updated `static/generated/` files with the source changes. Generated web assets are versioned; `dist/` and raw inputs are not. The bundled `static/js/projection-map.js` is generated by npm but kept with the site so normal previews do not need Node.

## Add a project

Copy an existing JSON file in `content/projects/`, give it a unique `slug`, update its metadata and writing, and place generated map images under `static/generated/`. Every project uses the same Overview, Maps, Methods, and Data template. The build validates required fields and checks that referenced map images exist. Include the new generated assets in the same commit as the project.

## Data and attribution

See `data/README.md`. Map-level attribution is also displayed beside the corresponding output. Raw datasets are excluded from version control, while reviewed web derivatives are included.

## Deployment

The included GitHub Actions workflow installs Node and Python, bundles the interactive map, and builds the site from the committed `static/generated/` assets. It does not download raw GIS data or run `portfolio-maps`. The workflow builds with the repository name as the base path and publishes `dist/` to GitHub Pages. Enable **Settings → Pages → Source → GitHub Actions** in the repository. No secrets or API keys are required. Future agents should preserve this deployment model; see `AGENTS.md`.
